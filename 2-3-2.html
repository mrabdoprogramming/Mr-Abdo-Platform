الصفحة

عندما تنقر على رابط أو تبدأ بحثًا، يطلب المتصفح غالبًا البيانات التي يحتاجها من خدمة على خادم عبر الشبكة. المتصفح هنا عميل (client) يرسل طلبًا، ويعيد الخادم (server) استجابة. وتحدد بروتوكولات مثل HTTP قواعد هذا التبادل. ويُعد نموذج الطلب والاستجابة أساسيًا في كثير من تطبيقات الويب، مع وجود وسائل اتصال أخرى عند الحاجة.

❓ السؤال الرئيسي: كيف يتواصل العميل والخادم لتشغيل تطبيق الويب، وما القواعد والرسائل التي يستخدمانها؟
1️⃣

الجزء الأولالعميل والخادم

(1) العميل Client

برنامج أو جهاز يرسل طلبًا إلى خدمة أخرى؛ ومن أمثلته متصفح الويب وتطبيق الهاتف.

(2) الخادم Server

الجانب الذي يستقبل الطلبات من العملاء، ويعالجها، ويعيد الاستجابات.

(3) تعتمد كثير من تطبيقات الويب على إرسال العميل طلبًا وإعادة الخادم استجابة.

🙋 العميل (المتصفح / تطبيق الهاتف)

يرسل الطلب: "أرني هذه الصفحة".

🖥️ الخادم (خادم الويب / خادم التطبيقات)

يرسل الاستجابة: إعادة البيانات المطلوبة.

يطلب العميل البيانات أو المعالجة؛ ويعالج الخادم الطلب ويعيد استجابةً.

✨ نفحات مستر عبدو

  • العميل = الزبون اللي بيطلب، والخادم = اللي بيخدم الطلب ويرد.
  • مثال: كتابتك لعنوان موقع في المتصفح = طلب، وظهور الصفحة = استجابة.

💡 حتة زيادة

العميل مش بس المتصفح! تطبيق الهاتف كمان عميل. والخادم نفسه ممكن يبقى عميل لخدمة تانية لو طلب منها بيانات. المهم الدور: مين اللي بيطلب ومين اللي بيرد.

2️⃣

الجزء الثانيHTTP وHTTPS

(1) HTTP بروتوكول نقل النص التشعبي

بروتوكول يُستخدم لتبادل الرسائل بين عميل وخادم على الويب.

(2) HTTPS

استخدام HTTP عبر اتصال TLS (Transport Layer Security) آمن. يساعد TLS على حماية سرية الاتصال وسلامته، وعلى مصادقة الخادم، بحيث لا يستطيع المتجسس قراءة المحتوى أو تعديله بسهولة أثناء النقل.

(3) المواقع التي تبدأ عناوينها بـ https:// تستخدم اتصال HTTPS.

✨ نفحات مستر عبدو

  • HTTP = لغة الحديث بين العميل والخادم.
  • HTTPS = نفس اللغة لكن داخل "ظرف مغلق ومشفّر" (TLS).
  • الحرف S في HTTPS يعني Secure (آمن).

🔗 حتة زيادة: ربط بالوحدة الثانية

HTTPS و TLS هما نفسهم اللي اتعلمناهم في درس التشفير والمصادقة: مصافحة TLS، والشهادة الرقمية، والتشفير بالمفتاح العام ثم المتماثل. يعني السؤال ممكن يجمع الدرسين.

🛑 توقّف وفكّر

لماذا يجب أن تستخدم صفحة تسجيل الدخول HTTPS بدلًا من HTTP العادي؟
الإجابة
لأن صفحة تسجيل الدخول تنقل بيانات حساسة (اسم المستخدم وكلمة المرور)، ويحمي HTTPS سرية الاتصال وسلامته عبر TLS، فلا يستطيع المتجسس قراءة هذه البيانات أو تعديلها بسهولة أثناء النقل.
3️⃣

الجزء الثالث · (1)طلبات HTTP والاستجابات: طريقة طلب HTTP

تتضمن الطلبات المرسلة من العميل إلى الخادم معلومات تسمى طريقة طلب HTTP توضح "نوع العملية المطلوبة".

الأسلوبالدورأمثلة
GETيُستخدم عادةً لطلب مورد أو بيانات من الخادمعرض صفحة ويب، استرجاع نتائج البحث
POSTيُستخدم عادةً لإرسال بيانات ليعالجها الخادمإرسال معلومات تسجيل الدخول، إرسال محتويات نموذج

✨ نفحات مستر عبدو

  • GET = "هات" (أريد أن آخذ بيانات).
  • POST = "خُذ" (أريد أن أرسل بيانات لتعالجها).

💡 حتة زيادة

  • في GET بيانات الطلب بتظهر غالبًا في العنوان (الرابط) نفسه، علشان كده ما نستخدمهاش لإرسال كلمة المرور. نستخدم POST لإرسالها (مع HTTPS طبعًا).
  • كلمة "عادةً" مهمة: GET و POST ليهم استخدامات أخرى، لكن دي الاستخدامات المعتادة اللي المنهج يركز عليها.
🚦

الجزء الثالث · (2)رمز حالة HTTP

تتضمن الاستجابات المرسلة من الخادم إلى العميل رقمًا يشير إلى نتيجة المعالجة، يسمى رمز حالة HTTP.

رمز الحالةالمعنى
200نجاح (تمت معالجة الطلب بنجاح)
404المورد المطلوب غير موجود بهذا العنوان
500خطأ داخلي في الخادم منعه من إكمال الطلب؛ ولا يحدد الرمز وحده السبب التفصيلي

✨ نفحات مستر عبدو

  • 200 = تمام، وصلت الصفحة ✅
  • 404 = العنوان مفيهوش حاجة (الصفحة غير موجودة) ❓
  • 500 = حصلت مشكلة جوه الخادم نفسه ⚠️

💡 حتة زيادة: التصنيف العام للأرقام (معلومة خارج الجدول)

أول رقمالمعنى العام
2xxنجاح
4xxمشكلة في الطلب (زي العنوان الخاطئ)
5xxمشكلة في الخادم

يعني 404 مشكلتها في العنوان المطلوب، و500 مشكلتها داخل الخادم.

🛑 توقّف وفكّر

إذا استقبل المتصفح رمز حالة 404 HTTP، ماذا يجب أن يخبر المستخدم، وأي جانب كانت به المشكلة؟
الإجابة
يخبره أن المورد (الصفحة) المطلوب غير موجود بهذا العنوان. الخادم عمل وردّ، لكنه لم يجد المورد المطلوب، فالمشكلة في العنوان المطلوب (كأن تكون الصفحة مفقودة أو العنوان خاطئًا)، وليست خطأ داخليًا في الخادم كما في الرمز 500.

4️⃣

الجزء الرابعواجهة برمجة التطبيقات (API)

(1) API Application Programming Interface

مجموعة قواعد واضحة تسمح لبرنامج بطلب بيانات أو وظائف من برنامج آخر. وهي واجهة أو عقد محدد للتواصل بين البرمجيات.

(2) الواجهة الأمامية والخدمة الخلفية

قد ترسل الواجهة الأمامية طلبات إلى خدمة خلفية عبر API وتستقبل منها البيانات.

✨ نفحات مستر عبدو

  • الـ API مثل "قائمة الطلبات" في المطعم: تحدد ما يمكنك طلبه وبأي شكل، من غير ما تدخل المطبخ.
  • JSON هو الشكل اللي بيتقدم بيه الرد: أزواج "مفتاح: قيمة" مثل "city": "Cairo".

(3) صيغة JSON

قد تعيد API بيانات بصيغة JSON (JavaScript Object Notation)، وهي صيغة نصية شائعة لتمثيل وتبادل البيانات المهيكلة باستخدام كائنات ومصفوفات وقيم بسيطة، وتدعمها لغات وأدوات برمجية كثيرة.

{ }

الجزء الرابع · تكملةتفاصيل JSON وقراءة البيانات

{
  "city": "Cairo",
  "temperature": 31
}
{ } أقواس معقوصةالمفتاح keyقيمة نصيةقيمة رقمية

💡 حتة زيادة: قواعد JSON

  • JSON بيتكتب بين أقواس معقوصة { }، وكل عنصر بشكل "المفتاح": القيمة، وبين العناصر فاصلة.
  • النص بيتحط بين علامتي تنصيص "Cairo"، أما الرقم فبدون علامات 31.
  • ميزة JSON: مقروء للبشر ومهيكل وبتدعمه لغات كتير، فسهل تبادل البيانات بين برامج مختلفة.

📖 اقرأ البيانات (JSON)

تأمّل البيانات أعلاه، ثم حدّد مفتاحًا (key) واحدًا والقيمة (value) المقابلة له.
الإجابة
المفتاح "city" وقيمته "Cairo". (ويمكن أيضًا: المفتاح "temperature" وقيمته 31).

💬 إجابة السؤال الرئيسي

في كثير من الحالات يرسل العميل طلبًا ويعيد الخادم استجابة وفق قواعد HTTP، وقد تستخدم التطبيقات وسائل أخرى عند الحاجة. يحدد HTTP طريقة تبادل الرسائل، ويستخدم HTTPS اتصال TLS آمنًا. وتوضح طريقة HTTP الغرض من الطلب؛ فيستخدم GET عادةً لطلب مورد أو بيانات، وPOST لإرسال بيانات ليعالجها الخادم. وتبين رموز الحالة نتيجة معالجة الطلب. وقد تستخدم التطبيقات API وقواعد واضحة لتبادل البيانات، وربما تمثلها بصيغة JSON النصية المهيكلة.

✅ الخلاصة: تذكّر: العميل يطلب، والخادم يستجيب، عبر HTTPS/HTTP، بأسلوب (GET/POST)، ورمز حالة، وغالبًا واجهة برمجة تطبيقات تعيد بيانات JSON.
🧠

فكّر وتحدَّ نفسكتأمل وتحدٍّ

💭 تأمل

عندما تفشل صفحة في التحميل، أي رمز حالة سيساعدك أكثر على فهم السبب، وماذا سيخبرك؟
إجابة مقترحة
الرمز 404 يخبرني أن الصفحة أو المورد غير موجود بهذا العنوان، والرمز 500 يخبرني أن الخادم نفسه واجه خطأ داخليًا منعه من إكمال الطلب (دون تحديد السبب التفصيلي).

🚀 التحدي

اذكر تطبيقًا واحدًا تستخدمه وصف طلبًا واحدًا يرسله والاستجابة التي يتوقعها.
إجابة مقترحة (تطبيق طقس)
يرسل طلب GET يطلب توقعات القاهرة، ويتوقع استجابة برمز 200 تحمل بيانات التوقعات بصيغة JSON.
جرّب بنفسك: فكّر في تطبيق على هاتفك: ماذا يطلب؟ بأي أسلوب (GET أم POST)؟ وبأي رمز حالة يتوقع أن يردّ الخادم؟
